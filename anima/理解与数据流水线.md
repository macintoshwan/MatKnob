# MegKnob 磁轴采集系统：理解与数据流水线

## 1. 系统定位

当前 MegKnob 固件不是 USB 键盘，而是一台 24 通道磁轴电压采集仪：USB HID 与 BLE 已关闭，设备只通过 USB CDC ACM 虚拟串口持续发送采样帧。上位机将二进制帧解码为 24 路毫伏数据，并绘制为实时波形。

完整链路为：

```text
磁铁靠近霍尔传感器
  → 传感器输出电压下降
  → 3 × 74HC4051 共享地址线并行选通同一 Y 通道
  → nRF52840 SAADC 一次批量读取 3 路公共端
  → 8 个地址组成 24 路完整扫描
  → 原始 ADC 值换算为 mV
  → 组成固定 62 字节 v3 帧并计算 CRC
  → 消息队列与 USB CDC TX 中断发送
  → Python 串口线程寻找魔数、验 CRC、解包
  → 有界实时缓存
  → PyQtGraph 绘制 24 路电压曲线
```

## 2. 磁轴如何变成电压

磁轴键帽下的磁铁随按键下压靠近霍尔传感器，磁场变化被传感器转换为模拟电压。当前硬件与阈值逻辑表现为“越按下，电压越低”：

- 未按状态通常处于较高电压区；
- 低于 `900 mV` 判定按下；
- 已按状态升到 `1400 mV` 以上才判定释放；
- `900–1400 mV` 是滞回区，避免阈值附近抖动；
- 状态变化还需连续 3 次扫描一致才确认。

视频重点展示连续电压，而不是只展示 0/1 键值，因为连续曲线正是磁轴后续实现触发行程和 Rapid Trigger 的基础。

## 3. 74HC4051 如何切换 24 个通道

硬件使用三片 8 选 1 模拟多路复用器 U26、U27、U28。三片芯片共享三根地址线：

| 地址位 | MCU GPIO |
|---|---|
| ADR0 | P1.06 |
| ADR1 | P0.09 |
| ADR2 | P0.10 |

三片 4051 的公共端分别进入三路 SAADC：

| 4051 | ADC 输入 | MCU 引脚 | 固件 row |
|---|---|---|---:|
| U26 | AIN7 / ADC7 | P0.31 | 0 |
| U27 | AIN5 / ADC5 | P0.29 | 1 |
| U28 | AIN0 / ADC0 | P0.02 | 2 |

地址设为 `Yk` 时，三片 4051 同时选中各自的 `Yk`，因此一次 ADC batch read 得到 3 个样本。遍历 8 个地址即得到 `3 × 8 = 24` 路数据。

固件采用 Gray 码顺序：

```text
0 → 1 → 3 → 2 → 6 → 7 → 5 → 4
000 001 011 010 110 111 101 100
```

相邻地址仅改变一个 GPIO，减少地址翻转及模拟切换噪声。每次改地址后忙等 `10 µs`，让模拟通路稳定。代码只写入发生变化的地址位。4051 的使能脚没有进入设备树，也不受固件控制；根据项目硬件排查记录，它应由硬件保持低电平使能。

## 4. ADC 如何采样

nRF52840 SAADC 当前配置：

- 12-bit；
- 内部 `0.6 V` 参考；
- `ADC_GAIN_1_6`，有效满量程约 `3.6 V`；
- acquisition time 为 `3 µs`；
- 无过采样；
- 无 dummy read。

`kscan_adc_mux_read_channels()` 每个地址调用一次 Zephyr `adc_read()`，通过 channel mask 批量采集 ADC0、ADC5、ADC7。Zephyr 按 ADC channel ID 升序存储结果，代码用 `POPCOUNT` 找回设备树中每个 row 对应的样本，再用 `adc_raw_to_millivolts_dt()` 转换为毫伏。

完整扫描由 `kscan_adc_mux_read()` 完成：8 次地址切换 × 每次 3 路采样。写入数组时使用：

```text
idx = row × 8 + col
```

所以线上固定顺序为：

```text
U26 Y0..Y7, U27 Y0..Y7, U28 Y0..Y7
```

实测最终版本完整扫描率约 `1216 Hz`，平均周期 `0.822 ms`，扫描主体约 `610 µs`。

## 5. 如何打包与传输

每次完整扫描后，`hall_stream_enqueue()` 构造固定长度的 62 字节小端 v3 帧：

| 偏移 | 字节 | 字段 |
|---:|---:|---|
| 0 | 2 | 魔数 `MK` |
| 2 | 1 | 版本 `3` |
| 3 | 1 | 类型：data / mode / perf |
| 4 | 1 | 显示模式：U26 / U27 / U28 / ALL |
| 5 | 1 | 样本数，数据帧为 `24` |
| 6 | 2 | `uint16` 序列号 |
| 8 | 4 | `uint32` 微秒时间戳 |
| 12 | 48 | 24 × `uint16` 毫伏样本 |
| 60 | 2 | CRC-16/CCITT-FALSE |

CRC 覆盖前 60 字节，初值 `0xFFFF`，多项式 `0x1021`。固件内部使用 16 项 nibble 查表实现。

帧进入深度为 4 的 `k_msgq`。如果队列已满，固件丢弃最旧帧而不是阻塞采样，以保持实时性。独立发送线程先检查主机 DTR，再开启 UART TX 中断；回调使用 `uart_fifo_fill()` 将整帧批量放入 CDC ring buffer。

## 6. 上位机如何接收和绘制

`tools/megknob_hall_viewer.py` 的 `SerialReader` 在线程中完成接收：

1. 以 115200 的名义波特率打开 USB CDC，并拉高 DTR；
2. 每次最多读取 512 字节到 `bytearray`；
3. `decode_frames()` 搜索 `b"MK"` 魔数；
4. 数据不足 62 字节则等待下一批；
5. CRC 错误时丢弃 1 字节并重新同步；
6. 使用 `struct.Struct("<2sBBBBHI24HH")` 小端解包；
7. 拒绝非 v3 帧；
8. 展开约每 71.6 分钟回绕一次的 32-bit 微秒时间戳；
9. 将已解码数据放入最大 64 帧的有界队列。

GUI 每 40 ms（25 FPS）取走待处理帧。历史缓存只保留当前可见时基约 110% 的数据，并在绘图前限制到约 1000 点。绘图时把毫伏除以 1000 转成伏特：

```python
curve.setData(x, data[:, ch] / 1000.0)
```

PyQtGraph 开启视口裁剪和 peak downsampling，可以稳定绘制最多 24 条实时曲线。这里再次采用“旧数据价值低于实时数据”的策略：队列积压时主动丢旧帧，优先维持低显示延迟。

## 7. 事实边界

- 代码能够确认地址线、ADC 通道、阈值、时序、帧结构和完整软件链路。
- 代码没有记录霍尔芯片具体型号，因此动画使用通用“线性霍尔传感器”表达，不虚构器件型号。
- 代码不控制 4051 的 Enable；动画将其画为硬件常使能，并注明这是基于硬件记录的判断。
- 24 个采样槽位全部发送，但当前物理按键映射表只列出 MEG0–MEG18；动画把它们称为“24 个采样通道”，不声称均已安装按键。
