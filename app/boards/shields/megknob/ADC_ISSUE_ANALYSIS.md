# MegKnob ADC 磁轴误触发分析报告

## 当前现象

用户实测映射关系本身基本正确，但仍存在串键/错键：

| 实际按下 | 当前输出 |
|---|---|
| Shift | R |
| Z | Space |
| A | F |
| F | TAB + A |

之前把 4051 地址切换后的等待时间从 `20us` 提高到 `200us`，并加入 ADC dummy read 后，情况“稍微有所改善”，说明问题和采样稳定性有关，但还没有完全解决。

## 当前固件映射关系

当前文档 [MEG_MAPPING.md](MEG_MAPPING.md) 中的 MEG 到 4051 映射表暂时认为是正确的，不优先怀疑 keymap 顺序。

目前更可疑的是：

1. **4051 地址切换后的模拟电压未完全稳定**
   - 4051 输出端、电路走线、SAADC 输入采样电容都会造成残留。
   - 之前增加 settle time 和 dummy read 后有改善，支持这个判断。

2. **三路 ADC 输入之间存在串扰或浮动**
   - 典型例子：`F -> TAB + A`，说明一次按键可能让多个 RC 被判定低于阈值。
   - 如果某些未按通道电压被瞬间拉低到阈值以下，就会触发其他键。

3. **某些 4051 Y 通道或 MEG 线路可能存在焊接桥连/虚焊**
   - `Shift -> R`、`Z -> Space` 这类跨芯片/跨通道错键，若稳定复现，也可能是 PCB/飞线/焊接问题。
   - 明天应重点检查错键对应的 MEG 线路和 4051 引脚是否短接。

4. **阈值窗口可能仍偏宽**
   - 已知未按约 `1.5V`，按下约 `0.8V`。
   - 当前阈值是 `<1000mV` 按下、`>1300mV` 释放。
   - 为减少误触发，可以进一步改成 `<900mV` 按下、`>1400mV` 释放。

## 错键对应检查点

按当前映射，建议明天优先检查：

| 实际按下 | 实际通道 | 错误输出 | 错误通道 | 检查重点 |
|---|---|---|---|---|
| Shift | MEG10 / U26 Y0 | R | MEG4 / U28 Y4 | MEG10 与 MEG4 线路、U26 Y0、U28 Y4、地址线组合 |
| Z | MEG11 / U26 Y7 | Space | MEG14 / U28 Y7 | 两者同为 Y7，不同 4051，重点查三路 ADC 公共端是否串扰 |
| A | MEG6 / U26 Y6 | F | MEG9 / U28 Y6 | 两者同为 Y6，不同 4051，重点查三路 ADC 公共端和同地址通道串扰 |
| F | MEG9 / U28 Y6 | TAB + A | MEG0 / U26 Y2 + MEG6 / U26 Y6 | U28 Y6 按下时 U26 通道误低，重点查 ADC 公共端、电源/GND、4051 使能和地址线稳定性 |

其中 `Z -> Space`、`A -> F` 都是**相同 Y 通道、不同 4051**之间错触发，这更像 ADC 输入间串扰/公共端干扰，而不是 transform 顺序错。

## 固件侧保守策略

本次准备采用更保守的固件策略：

1. 地址切换等待时间继续增加：`200us -> 500us`。
2. 每次 ADC 仍保留 dummy read。
3. 阈值收紧：
   - 按下：低于 `900mV`
   - 释放：高于 `1400mV`
4. 新增连续扫描确认：
   - 连续 3 次扫描都判断为按下，才发送按下事件。
   - 连续 3 次扫描都判断为释放，才发送释放事件。

这样会牺牲一点响应速度，但可以显著减少短暂串扰造成的多键误触发。

## 如果保守固件仍串键

如果这版仍出现稳定串键，优先怀疑硬件而不是 keymap：

1. 测每个 4051 的公共端 ADC 输入：
   - 未按是否都稳定约 `1.5V`
   - 按下是否只对应一路降到约 `0.8V`
   - 其他两路 ADC 是否也被拉低
2. 固定地址线状态，逐个测 Y 通道：
   - 同一地址下，三片 4051 的输出是否互相影响
3. 检查 4051 的 `E` 使能脚是否都可靠接地。
4. 检查 `VEE/GND/VCC` 是否符合 74HC4051 模拟开关使用要求。
5. 检查 CHR605 供电/GND 是否有共地不良或焊桥。
